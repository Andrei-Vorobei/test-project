# LOM AI — учебный помощник

Frontend-прототип чата с локально имитируемым образовательным AI-агентом.

Подробное описание архитектуры и работы кода находится в [manual.md](./manual.md). В руководстве разобраны структура проекта, Redux-состояние, mock-agent, потоковая генерация, пользовательские сценарии и демонстрация приложения.

## Запуск

```bash
npm install
npm run dev
```

Для проверки:

```bash
npm run lint
npm run build
npm test
```

## Деплой на Netlify

В репозитории есть [netlify.toml](./netlify.toml) с настройками сборки Vite:

- команда сборки: `npm run build`;
- опубликованная папка: `dist`;
- версия Node.js: `22`;
- fallback на `index.html` для маршрутов клиентского приложения.

Чтобы включить автоматический деплой из GitHub:

1. Отправьте репозиторий в GitHub.
2. В Netlify выберите **Add new project → Import an existing project → GitHub**.
3. Выберите этот репозиторий и разрешите Netlify доступ к нему.
4. Проверьте настройки сборки и нажмите **Deploy**. Netlify автоматически прочитает `netlify.toml`.
5. После этого каждый push в выбранную production-ветку будет запускать новую сборку и публикацию.

Перед подключением можно проверить production-сборку локально:

```bash
npm run build
npm run preview
```

## Стек и структура

- React 19, TypeScript, Vite.
- Redux Toolkit и React Redux — состояние списка диалогов, активного диалога и сообщений.
- `src/app/` — Redux store и типизированные хуки.
- `src/features/chat/` — модель данных, сохранение, Redux slice, mock-agent, тесты и компоненты чата.
- `src/App.tsx` — сборка основного интерфейса.

## Состояние приложения

У каждого диалога есть отдельная история и независимое состояние генерации. Redux Toolkit обрабатывает действия mock-agent, а request ID не позволяет поздним событиям менять ответ другого или уже завершённого запроса. При переключении диалога генерация продолжается в исходном диалоге. Диалог можно удалить после подтверждения; если удалён активный чат, выбирается следующий доступный, а события его остановленной генерации игнорируются.

Список диалогов, активный диалог и история сообщений сохраняются в `localStorage`. Во время генерации текст сохраняется по завершении запроса; после перезагрузки незаконченный ответ становится доступен для повтора. Невалидные или недоступные сохранённые данные приводят к понятному уведомлению.

## Mock-agent и события

`src/features/chat/mockAgent.ts` содержит независимый от UI и Redux mock-agent. Он с небольшой задержкой выдаёт типизированные события: статусы, вызов и результат калькулятора, фрагменты ответа, завершение или ошибку.

Агент поддерживает несколько образовательных сценариев и учитывает предыдущий ответ, если пользователь просит объяснить проще. Для демонстрации инструмента можно спросить, например, «Сколько будет 17 × 24?». Чтобы проверить ошибку и повтор, отправь «вызови ошибку».

`npm test` проверяет сценарии mock-agent, повтор неуспешного запроса, защиту от устаревших событий при переключении диалога и удалении активного чата, а также восстановление незаконченного ответа после перезагрузки.

Desktop- и touch-сценарии дополнительно проверены в headless Edge при ширине 1440 и 390 px: отправка сообщения, ответ калькулятора, ошибка и повтор, изменение размера поля, удаление активного диалога во время генерации. Горизонтального переполнения и ошибок JavaScript не обнаружено.

## Архитектурные решения и ограничения

- Redux Toolkit централизует состояние диалогов и сообщений.
- Mock-agent отделён от UI и Redux; приложение работает без настоящей модели, AI API и backend.
- В шапке доступно переключение светлой и тёмной темы; выбранная тема сохраняется в `localStorage`.
- На мобильном экране список диалогов открывается как боковая панель, а действия доступны без hover.
- Учитывается настройка reduced motion; декоративные кнопки без действия не отображаются.

## Использование AI-инструментов

В процессе разработки использовался Copilot.

- Проект был создан на базе шаблона Vite. В процессе обсуждения агент предложил Zustand для управления состоянием, но для этого проекта было принято решение использовать Redux Toolkit: я настоял на Redux, поскольку он лучше соответствует требованиям задания и выбранной архитектуре.
- В процессе разработки я предложил добавить удаление диалогов. Для этого сценария были реализованы подтверждение действия, выбор другого диалога после удаления активного и очистка состояния его генерации.
- Я также предложил добавить переключение светлой и тёмной темы. Выбранная тема сохраняется в `localStorage`, а переключатель доступен в шапке приложения.
- Критических ошибок в работе приложения не обнаружено. Во время проверки некорректно работало изменение размера поля ввода промпта; проблема была описана агенту и исправлена в процессе разработки.
- При проверке функционала выяснилось, что строка с датой вида `2026-11` распознаётся калькулятором как арифметическое выражение. Исправление не вносилось: это известное ограничение простого локального распознавателя выражений, а не основной сценарий приложения.

Важным результатом итеративной проверки стало улучшение отображения результатов инструментов: история вызова калькулятора сохраняется в сообщении ассистента и остаётся видимой после завершения ответа. Прерванные перезагрузкой ответы также восстанавливаются как ошибки с возможностью повторной попытки, а не как завершённые ответы.
